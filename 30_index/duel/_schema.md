# 同路对位矩阵 · 数据结构说明

> 这份文档解释 `30_index/duel/` 下的文件长什么样、每个字段什么含义、
> 以及为什么某些格子宁可空着。改数据前先读这一页。

## 为什么要有这个东西

用户的原话是：「不知火舞和哪个中路五五开、克制哪个中路，，，这样例也太 tm 少了吧」。

查下来根因不在「采得不够多」，在**口径错了**：

| 来源 | 总数 | 其中同路 |
|---|---|---|
| 官方关系页 463 条方向边 | 463 | **106 条（23%）** |
| 现有 K-B 实测条目 | 42 | **4 条** |
| 视频字幕候选 | 287 | **20 条** |

官方边有 77% 是跨路对位（打野抓中路、边路打辅助），从来没按同路采集过。
一旦把问题收窄成「中路 31 个英雄两两之间」，可用的答案就掉到 5% 以下。

所以这个矩阵不是「再多写几条卡」，是**换一个坐标系重新采**：
同一路里所有英雄两两配对，一格一格填。

## 文件

| 文件 | 谁生成 | 是什么 |
|---|---|---|
| `{lane}.grid.json` | `s24_duel_grid.py` | **成品**。N×(N-1) 个格子，站点直接读 |
| `{lane}.verdicts.jsonl` | 人手写 | 人工裁决。唯一允许主观判断的入口 |
| `{lane}.col_verdicts.jsonl` | `s25_duel_aggregate.py` | 专栏自动聚合的裁决，**优先级低于人工** |
| `{lane}.column_edges.jsonl` | `s23_parse_columns.py` | 专栏原文拆出来的原始边，未归并 |
| `{lane}.queue.json` | `s24 --queue` | 待判队列，按冲突/证据量排序 |
| `_schema.md` | 人 | 本文件 |

上一层的原料在 `10_sources/`（已 gitignore，正文有版权不进仓库）：

- `10_sources/bili_cache/article/{cv}.json` — 专栏全文缓存，抓一次不再抓
- `10_sources/creators_cache/subs/{bv}.json` — 视频字幕
- `10_sources/official/{ename}.json` — 官方详情页

## 一个格子长什么样

```json
{
  "key": "mid|女娲|海月",
  "a": "女娲", "b": "海月",
  "grade": "被克",
  "status": "measured",
  "basis": "video",
  "layer": "机制",
  "conf": "high",
  "cond": "S45 · 全程 · 海月免控在场且大招可用",
  "how": "别跟她拼线权……",
  "counter": "海月的免控和大招都有 CD……",
  "ev": [{"kind": "video", "ref": "BV1K8gDzwEho", "ts": 0,
          "quote": "海月对线女娲八二开", "url": "https://..."}],
  "mirror_of": "",
  "updated": "2026-11-01",
  "by": "human"
}
```

`grade` 永远是**从 `a` 的视角**说的：`a` 克 `b` 就是 `"克"`。
另一侧 `mid|海月|女娲` 由脚本按反对称自动补，不重复判断。

## 三个枚举，不许混用

### 档位 `grade`（五档）

| 值 | 含义 | 判断标准 |
|---|---|---|
| `克` | 明显克制 | 机制层面废掉对方核心手段，10-0 到 8-2 |
| `小优` | 小幅领先 | 有优势但能被操作/出装抹平，7-3 到 6-4 |
| `五五开` | 均势 | 两边都能打，看谁先手 |
| `小劣` | 小幅落后 | `小优` 的反面 |
| `被克` | 明显被克 | `克` 的反面 |

**反对称是硬约束**：`grade(b,a)` 必须等于 `INV[grade(a,b)]`。
所以真正要判的只有 N×(N-1)/2 个无序对，另一侧脚本镜像。

### 状态 `status`（三态）

| 值 | 含义 | 站点上的样子 |
|---|---|---|
| `measured` | **有人真讲过**，点得开原话 | 实底 |
| `derived` | 只有方向、没有原文（官方 L0），或机制推演 | 45° 斜纹 + 虚线边 |
| `empty` | 还没找到来源 | 极淡棋盘 |

**`empty` 不是「五五开」。** 这两件事在实战里差很远：
一个是「确实均势」，一个是「我们不知道」。混淆它们就是造假。
站点上专门写了这句话，改文案时别删。

### 依据 `basis`（derived 必填）

`column` 专栏 / `video` 视频 / `official` 官方关系页 / `mechanism` 机制推演

## 可信度 `conf`

`low` / `mid` / `high`。规则由 `s25` 定：来源 1 篇 = low，2 篇 = mid，3 篇以上 = high。
`high` 还额外要求至少 2 条证据，审计第 4 项会拦。

## 三个解析分支 + 两条闸门

专栏正文拆边（`s23`）不是一把正则通吃，是三条独立分支，各自统计正确率：

| 分支 | 长什么样 | 方向怎么定 |
|---|---|---|
| **B1 箭头行** | `铠<-蒙恬、吕布` | 箭头**头**指向被克的一方 |
| **B2 句内动词** | `X克制Y`、`X打不过Y`、`X和Y五五开` | 动词夹在两个名字中间 |
| **B4 括号列表** | `女娲（不知火舞）` | 括号里的是治他的 |

**否定闸门**：句子出现「不克制/不算/谈不上/克制不是」整句丢弃。
**跨句闸门**：动词必须在两个英雄名之间且同句——跨句的因果全靠脑补。

踩过的坑记在这里：
- 「不知火舞」的「不」被当成否定词，整条 `女娲（不知火舞）` 被吞。改成先抠掉英雄名再查剩余字符。
- 「被克」类模式的档位取反逻辑写错，导致「克制X的是Y」方向全反（姜子牙克甄姬被记成姜子牙被甄姬克）。现在所有模式只声明**赢家的档位**，方向由 `xy`/`yx` 单独决定。

## 英雄池：为什么是 31 个不是 24 个

官方 `roles` 字段的**顺序不可靠**。`main_lane` 取的是第一个：

- 诸葛亮 → `jungle`（他确实常打野，但中路对位必须有他）
- 大乔 → `mid`（她实际是游走）

所以矩阵英雄池用 `lanes` **全集**，不用 `main_lane`。
`names.py` 里 `in_lane()` 就是这个口径。

## 改数据的三条规矩

1. **只改 `{lane}.verdicts.jsonl`**，别手改 `grid.json`——下次跑 `s24` 会被覆盖。
2. **改完必须过审计**：`python 40_scripts/s26_duel_audit.py --lane mid --gate 1`。
   十项全绿才算数，返回码非 0 就别提交。
3. **`measured` 必须能点开原文**。写不出 `cond` 就降级 `derived`。

## 一条边从采到上线的完整链路

```
s22_collect_columns.py   搜专栏 → 抓全文 → 落缓存
   ↓
s23_parse_columns.py     正文拆边（B1/B2/B4 + 两条闸门）
   ↓
s25_duel_aggregate.py    归并去重 → 方向对账 → 定档 → 出 col_verdicts
   ↓
s24_duel_grid.py         骨架 + 官方种子 + 专栏裁决 + 人工裁决 + 镜像 → grid.json
   ↓
s26_duel_audit.py        十项机械校验
   ↓
build_site.py            压成位置数组 → #duel:{lane}
```

重跑任意一环都不会产生重复数据：`s23` 每次覆盖 `column_edges.jsonl`，
`s25` 每次覆盖 `col_verdicts.jsonl`，`s24` 每次从零建格子。
只有 `verdicts.jsonl` 是 append-only 的人工入口。
