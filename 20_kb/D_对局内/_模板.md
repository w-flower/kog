# 写作模板（新增环节时复制，规矩不许改）

## 三条硬规矩

1. **文件名是一个"决定"，不是话题。** 不许出现"英雄""铭文""出装"这类名词短语。必须是"04 对线期：这波线清完我该往哪走"这种带决策的。
2. **每节第一节必须是"上一节留下的问题"**，且点名上一节哪个分支留下了它。断链的节不许存在。
3. **易错点按环节归位，不单列。** 禁止"本节易错点：①②③"，错必须挂在它所属的判断节点下，写成"在这个节点上，人会这样错"。

---

## 环节文件模板

```markdown
---
id: NN
title: 环节名
depends_on: [上一节 id]
unlocks: [下一节 id]
role: [mid, roam]
version: S45
status: active
updated: YYYY-MM-DD
---

# NN 环节名：这一节回答的那一个决定

> **依赖**：XX（一句话说清传进来的是什么结论）
> **被依赖**：YY（本节产出什么，是 YY 的输入）

## 0. 上一节留下的问题
（点名上一节的哪个分支留下了它，不许写"上一节讲了基本概念"这种废话）

## 1. 本节只回答一个决定
（一句话，必须是问句，必须能直接回答"做/不做/去哪"）

## 2. 判断树
（代码块里画，每个叶子带 K id，每个分叉给判据+阈值，禁止"视情况而定"）

## 3. 判断依据
（表格：变量 / 在哪看 / 阈值 / 影响哪个分支）

## 4. 分支说明
（每条一个 K 条目）

## 5. 本节的连锁错误（按节点挂）
- 在节点「…」上：人会这样错……

## 6. 待验证 / 冲突
```

## K 条目模板（字段一个不能少）

```markdown
### K-NNNN 一句话说清这条要你做什么决定

- **适用版本**：S45（2026-09-23 起）；S46 待复核
- **触发条件**：（局面，要具体到时间点和状态）
- **判断依据**：（2–3 个可量化变量）
- **决策分支**：
  - 条件 A → 做 X
  - 条件 B → 做 Y
- **反例**：「某句常见说法」——为什么它是错的
- **依赖**：依赖 K-XXXX（为什么）；被 K-YYYY 依赖
- **来源**：BVxxxxxxxxx @ mm:ss；BVyyyyyyyyy @ mm:ss
- **可信度**：高 / 中 / 低（说明依据）
- **状态**：active / stale / conflict
```

### 字段纪律

- **来源里的 mm:ss 必须能在 `<BV>.cues.json` 里找到 ±3 秒的 cue**，`s5_index.py` 会机械校验，编造的直接判 `bad_timestamp`。
- **反例字段不许空**。写不出反例，说明你还没搞清这条的适用边界，标 `可信度: 低`。
- **判据必须可量化**。"打野在不在"行，"局势好不好"不行。
- **不许写"这个英雄很强"**，只能写"在什么条件下强"。
